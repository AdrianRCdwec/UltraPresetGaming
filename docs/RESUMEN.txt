CONTEXTO GENERAL DEL PROYECTO
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Estoy desarrollando "UltraPresetGaming", un proyecto web full-stack para mi Trabajo de Fin de Ciclo (TFC - 2º DAW). Es una aplicación web comparadora de precios de hardware y videojuegos entre distintas tiendas/plataformas. Se basa en el "Tipo 2" del trabajo: Frontend vanilla consumiendo un Backend propio.

Stack Tecnológico:
- Frontend: HTML5 semántico, CSS modular (variables, responsive) y JavaScript puro (Vanilla JS).
- Backend: Django (Python) + Django REST Framework exponiendo una API RESTful (GET, POST, PUT, PATCH, DELETE).
- Autenticación: Sistema basado en JWT. El token y el username se guardan en el localStorage.
- Base de Datos: SQLite (optimizada para concurrencia en lectura).

FUNCIONALIDADES DE INTERFAZ (FRONTEND)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
- Header dinámico (auth_header.js): Gestiona la sesión JWT, cambiando el botón de login por un enlace al perfil (/Perfil/perfil.html) con la foto del usuario o un avatar dinámico.

- Comparador: Vista principal (comparador.html) para visualizar y comparar precios.

MOTOR DE SCRAPING Y AUTOMATIZACIÓN (BACKEND/PYTHON)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Motor de scraping robusto usando Playwright (modo síncrono/multihilo) para extraer catálogos masivos de tiendas: PcComponentes, Coolmod, Alternate, LifeInformatica y NeoByte.

Evasión Antibot (stealth.py):
Tácticas avanzadas para evadir WAFs y Cloudflare Turnstile: resolución de captchas interactiva, perfiles dinámicos de navegador (User-Agent, Client-Hints), bloqueo de trackers y scroll humano biomético (retrasos aleatorios y movimientos curvos del ratón). Proxys residenciales apagados por defecto para la presentación.

Motor de Coincidencias IA (ia_matcher.py):
- Modelo de IA local (Ollama) con reglas estrictas por categoría (CPU, GPU, RAM, etc.).
- Sistema de dos niveles: Phi-3 (rápido) para casos claros y Llama 3 (pesado) para casos dudosos.
- NUEVO (Hilo 4): Validación y autocorrección de JSON añadida. Funciones auxiliares: normalizar_valor_json, validar_json_batch, convertir_json_a_resultados, solicitar_correccion_json y obtener_json_validado. Si el modelo devuelve un JSON inválido o mal estructurado, el sistema le pide una corrección automática antes de fallar. Si la corrección también falla, retorna False de forma segura sin tumbar el proceso.

Gestión de Base de Datos (db_manager.py):
- Sistema de inserción masiva (bulk_create, bulk_update) con caché en memoria RAM.
- Limpieza de ofertas caducadas (soft delete) basada en fechas de actualización.
- NUEVO (Hilo 4): Regex compiladas. Las constantes PATRON_PALABRAS_BASURA, PATRON_INTEL, PATRON_AMD, PATRON_GPU_NVIDIA, etc. se definen a nivel de módulo con re.compile() para que se compilen una sola vez al importar. La función limpiar_nombre_producto refactorizada para usar estas constantes, reduciendo el coste de procesamiento repetitivo.
- NUEVO (Hilo 4): Índices en BD. Añadidos db_index=True en los campos nombre y categoria del modelo Producto en api/models.py. Migración aplicada.

ARQUITECTURA DEL SCRAPER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
- Modularización: Lógica dividida en db_manager.py, ia_matcher.py y stealth.py.
- Patrón Factory: BaseScraper + ScraperFactory que instancia dinámicamente las clases hijas de cada tienda.
- Orquestador Multihilo (main_crawler.py): ThreadPoolExecutor con cálculo dinámico de hilos basado en RAM disponible (psutil).
- Sistema de Logging Profesional: logger.py centralizado con logging estándar de Python, thread-safe, escribe en terminal y persiste errores en scraper.log.

NUEVO (Hilo 4) - Reutilización de contextos de Playwright:
Antes: se abría un nuevo browser.new_context() por cada categoría (10 veces por tienda).
Ahora: BaseScraper expone iniciar_navegador() y cerrar_navegador(). Cada clase hija implementa iniciar_navegador() con toda la configuración stealth (perfiles, proxies, headers, anti-bot) UNA SOLA VEZ por tienda. El orquestador main_crawler.py llama a scraper.iniciar_navegador() antes del bloque de escaneos y a scraper.cerrar_navegador() en el finally. Flags de headless puro --no-sandbox, --disable-dev-shm-usage, --disable-gpu incluidos en todos los scrapers.

NUEVO (Hilo 4) - Graceful Shutdown:
Implementado en main_crawler.py mediante threading.Event (shutdown_event) y manejadores de señales signal.SIGINT y signal.SIGTERM. Al pulsar Ctrl+C: primera señal activa shutdown_event (apagado seguro, espera a que los hilos en curso guarden en BD y cierren Playwright). Segunda señal fuerza sys.exit(1). En cada scraper, dentro del bucle de paginación/carga hay una comprobación: if shutdown_event.is_set(): break. El bloque finally del main solo ejecuta desactivar_ofertas_obsoletas() si el script terminó de forma natural (no por interrupción).
