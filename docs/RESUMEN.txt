CONTEXTO GENERAL DEL PROYECTO
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Estoy desarrollando "UltraPresetGaming", un proyecto web full-stack para mi Trabajo de Fin de Ciclo (TFC - 2º DAW). Es una aplicación web comparadora de precios de hardware y videojuegos entre distintas tiendas/plataformas. Se basa en el "Tipo 2" del trabajo: Frontend vanilla consumiendo un Backend propio.

Stack Tecnológico:
- Frontend: HTML5 semántico, CSS modular (variables, responsive) y JavaScript puro (Vanilla JS).
- Backend: Django (Python) + Django REST Framework exponiendo una API RESTful (GET, POST, PUT, PATCH, DELETE).
- Autenticación: Sistema basado en JWT. El token y el username se guardan en el localStorage.
- Base de Datos: SQLite (optimizada para concurrencia en lectura).

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
FUNCIONALIDADES DE INTERFAZ (FRONTEND)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
- Header dinámico (auth_header.js): Gestiona la sesión JWT, cambiando el botón de login por un enlace al perfil (/Perfil/perfil.html) con la foto del usuario o un avatar dinámico.
- Carrito de Compras: Panel interactivo con pestañas de "Hardware" y "Videojuegos", sincronizado en tiempo real con la BD mediante POST y PATCH.
- Comparador: Vista principal (comparador.html) para visualizar y comparar precios.

MOTOR DE SCRAPING Y AUTOMATIZACIÓN (BACKEND/PYTHON)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Motor de scraping robusto usando Playwright (modo síncrono/multihilo) para extraer catálogos masivos de tiendas: PcComponentes, Coolmod, Alternate, LifeInformatica y NeoByte.

Evasión Antibot (stealth.py):
Tácticas avanzadas para evadir WAFs y Cloudflare Turnstile: resolución de captchas interactiva, perfiles dinámicos de navegador, bloqueo de trackers y scroll humano biométrico. Proxys residenciales apagados por defecto para la presentación.

Motor Híbrido de Coincidencias (NLP + IA):
- NUEVO (Hilo 5) - Filtro TF-IDF (Nivel 2): Se ha sustituido `fuzzywuzzy` por `scikit-learn` (TfidfVectorizer + cosine_similarity). La base de datos se vectoriza en memoria y los productos extraídos se comparan matemáticamente en milisegundos, resolviendo el 99% de los casos sin usar IA.
- IA Local como Fallback (Nivel 3): Ollama (Phi-3 / Llama 3) solo se invoca para casos verdaderamente dudosos.
- NUEVO (Hilo 5) - Reintentos (Retry & Timeout): Se ha añadido un bloque de reintentos en `ia_matcher.py` para que, si Ollama sufre un timeout por saturación, el script espere y reintente en lugar de descartar el producto.
- Validación JSON estricta (Hilo 4): Autocorrección de JSON añadida. Si el modelo devuelve un JSON inválido, el sistema pide corrección automática.

Gestión de Base de Datos (db_manager.py):
- Sistema de inserción masiva (bulk_create, bulk_update) con caché en memoria RAM.
- Limpieza de ofertas caducadas (soft delete).
- Regex compiladas (Hilo 4): Constantes pre-compiladas para extracción rápida de modelos clave.
- Índices en BD (Hilo 4): db_index=True en nombre y categoria.

ARQUITECTURA DEL SCRAPER
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
- Modularización: Lógica dividida en db_manager.py, ia_matcher.py y stealth.py.
- Patrón Factory: BaseScraper + ScraperFactory que instancia dinámicamente las clases hijas de cada tienda.
- Orquestador Multihilo (main_crawler.py): ThreadPoolExecutor con cálculo dinámico de hilos basado en RAM disponible (psutil).
- NUEVO (Hilo 5) - Limpieza de Entorno: Se han eliminado dependencias obsoletas (`fuzzywuzzy`, `Levenshtein`, `openai`) y se ha consolidado el stack matemático (`scikit-learn`, `numpy`, `scipy`).
- Reutilización de contextos de Playwright (Hilo 4): Perfiles y contextos iniciados UNA SOLA VEZ por tienda.
- Graceful Shutdown (Hilo 4): Apagado seguro mediante threading.Event y señales del sistema.
